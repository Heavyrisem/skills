# Advisor

원본 advisor는 파라미터 없는 도구다. 이 환경에는 advisor 도구가 없으므로, `spawn_subthread`로 리뷰어 프로파일의 서브스레드를 띄워 흉내낸다.

## 사전 조건

- 위임 설정이 "Only When Asked"인데 사용자가 이번 요청에서 위임을 요청하지 않은 경우, 내가 서브에이전트인 경우, `spawn_subthread` 도구가 보이지 않는 턴에서는 호출하지 않는다. 사용자에게 "advisor 호출 불가: <이유>"라고 한 줄로 알린다. 사용자의 승인 응답은 그 요청에 대한 답으로 듣고, 승인하면 이번 요청의 위임을 허용된 것으로 보고 호출하며, 승인하지 않으면 advisor 없이 진행한다.

## 호출 방법

`spawn_subthread(profile="reviewer", prompt=...)`로 호출한다. 모델은 Reviewer 프로파일 설정이 정하므로 넘기지 않는다. 서브스레드는 새 대화가므로 부모의 맥락을 상속받지 않는다. 원문을 재요약해 넘기지 않고, 리뷰어가 원문에 직접 접근하게 한다.

prompt에는 다음을 넣는다:

- 부모 스레드의 ID (ID는 `delta thread tree`로 확인)
- 사용자의 원래 요청 원문
- 현재 계획 또는 결과물, 그리고 검토 초점: 지금 판단하려는 결정, 관련 파일 경로, 에러 문자열, 키워드

그리고 리뷰어에게 아래를 지시한다:

1. terminal로 `delta thread show --format full <부모 스레드 ID>`를 실행해 transcript 원문을 파일로 내보내고, 그 원문을 기준으로 검토한다. 부모가 prompt에 준 요약은 안내용으로만 쓰고 근거를 대체하지 않는다.
2. 원래 요청 → 현재 계획 → 관련 결정과 실패 기록 순으로 읽고, grep으로 과거 근거를 역추적한다.
3. 부모가 준 키워드에만 의존하지 않고, 요구 변경, 반대 근거, 미해결 항목을 독립적으로 찾는다.
4. 보고서에 "확인한 범위 / 확인하지 못한 범위 / 추가 자료가 필요한지"를 의무로 포함한다. 맥락이 부족하면 판단을 보류하고 자료를 요청한다.

한계를 알려 둔다: 종료된 부모 턴은 CLI로 읽을 수 있지만, 진행 중인 부모 턴이 리뷰어에게 어디까지 보이는지는 보장되지 않는다.

## 모델

모델은 Delta의 Reviewer 서브에이전트 프로파일 설정을 따른다. 프로파일은 프로바이더별 `model` 값과 `[model.any]` 폴백을 갖는다 (예: macOS의 `~/Library/Application Support/delta/profiles/reviewer.toml`).

- `model`, `effort` 파라미터를 넘기지 않는다. 설정을 읽어 값을 직접 넘기지도 않는다. (`subagent_defaults.allow_parent_model_override`가 `false`면 부모가 모델을 지정할 수 없다.)
- 모델을 바꾸려면 Delta 설정의 Reviewer 프로파일에서 바꾼다.
- 생성이 실패하면 다른 프로파일이나 모델로 대체하지 않고 사용자에게 보고한다.

## 호출 시점

1. **실질 작업 전에**: 코드를 작성하거나 파일을 수정하거나, 해석을 확정하거나, 가정 위에 작업을 쌓기 전에 호출한다. 조언을 받기 전에는 실질 작업을 진행하지 않는다. (사전 조건에 따라 호출할 수 없는 경우는 예외.) 파일 찾기, 소스 확인 같은 탐색은 실질 작업이 아니므로 먼저 해도 된다. 순서는 "탐색 → advisor(계획 검토) → 사용자에게 범위 제시 → 확인 후 실행"이다.
2. **완료라고 판단했을 때**: 호출 전에 파일 저장까지 마친다. 커밋은 사용자가 요청한 경우에만 한다.
3. **막혔을 때**: 같은 에러가 반복되거나, 접근이 수렴하지 않거나, 결과가 예상과 맞지 않을 때.
4. **접근 방식을 바꾸려 할 때**.

## 빈도

- 여러 단계 작업: 접근을 확정하기 전에 1회 이상, 완료를 선언하기 전에 1회 이상.
- 짧은 반응형 작업(방금 본 출력이 다음 행동을 정해주는 경우): 반복 호출하지 않는다. advisor의 가치는 접근이 굳기 전 첫 호출에서 가장 크다.

## 조언 처리

- 조언에 큰 비중을 둔다.
- 실제로 시도해 봤는데 실패하거나, 1차 근거(파일 내용, 문서 등)가 조언과 다르면 그에 맞춰 조정한다.
- 자체 테스트가 통과했다는 것만으로 조언이 틀렸다고 보지 않는다. 테스트가 조언이 짚은 부분을 다루지 않을 수 있다.
- 내가 찾은 근거와 조언이 충돌하면 조용히 바꾸지 않고, advisor를 한 번 더 불러 충돌을 짚고 판단한다. **충돌로 인한 재호출은 1회까지.** 그래도 의견이 갈리면 양쪽 근거를 사용자에게 보고하고 판단을 받는다.
